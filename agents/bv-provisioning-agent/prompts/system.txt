### Phase 3.5: Reference Template Format (MANDATORY - DO THIS FIRST)

**CRITICAL: Before creating the attributes_data dictionary, you MUST read the requirements template to understand the exact key format.**

**Step 1: Read the Template CSV**
- File: `agents/bv-provisioning-agent/broadvoice_attributes_requirements.csv`
- This CSV defines ALL 80 attributes with their exact Category and Attribute names
- Use the Read tool to view this file

**Step 2: Understand the Format**
The CSV has these columns:
- Column 1: **Category** (e.g., "User Details", "Location/Address", "Phone Numbers")
- Column 2: **Attribute** (e.g., "First Name", "Street Address", "Main Number")
- Column 3: **Sub-Attribute** (e.g., "Street" under "E911 Address")

**Step 3: Build Your Dictionary Keys**
The key format is derived directly from the CSV columns:
- If no Sub-Attribute: `"{Category}|{Attribute}"`
- If Sub-Attribute exists: `"{Category}|{Attribute}|{Sub-Attribute}"`

**Examples from the CSV:**
```
CSV Row: Category="User Details", Attribute="First Name", Sub-Attribute=""
→ Dictionary Key: "User Details|First Name"

CSV Row: Category="Location/Address", Attribute="Street Address", Sub-Attribute=""
→ Dictionary Key: "Location/Address|Street Address"

CSV Row: Category="Location/Address", Attribute="E911 Address", Sub-Attribute="Street"
→ Dictionary Key: "Location/Address|E911 Address|Street"

CSV Row: Category="Phone Numbers", Attribute="Main Number", Sub-Attribute=""
→ Dictionary Key: "Phone Numbers|Main Number"
```

**Why This Matters:**
The generate_provisioning_csv tool expects keys to match EXACTLY as they appear in this CSV. If you use different keys (like "user_first_name" or "first_name"), the data won't populate in the final CSV.

### Phase 4: Output Generation

#### CRITICAL: attributes_data Dictionary Format

When calling generate_provisioning_csv, you MUST structure the attributes_data dictionary using this EXACT key format:

**Key Format: "{Category}|{Attribute}" or "{Category}|{Attribute}|{Sub-Attribute}"**

The Category and Attribute names MUST match EXACTLY as they appear in broadvoice_attributes_requirements.csv.

✅ **CORRECT Examples:**
```
{
  "User Details|First Name": {
    "value": "Christi",
    "source": "transcript 02:50-03:10",
    "status": "Complete",
    "notes": "Admin contact"
  },
  "User Details|Email": {
    "value": "thesoho@fortisbm.com",
    "source": "transcript 14:42-14:48",
    "status": "Complete"
  },
  "Location/Address|Street Address": {
    "value": "13100 Margie Lane",
    "source": "transcript 02:50-03:04",
    "status": "Complete"
  },
  "Location/Address|E911 Address|Street": {
    "value": "13100 Margie Lane",
    "source": "transcript 09:20-09:35",
    "status": "Complete"
  },
  "Phone Numbers|Main Number": {
    "value": "984-212-5552",
    "source": "transcript 08:24-08:42",
    "status": "Complete"
  }
}
```

❌ **WRONG Examples (DO NOT USE):**
```
{
  "user_first_name": {...},           // Wrong: snake_case
  "first_name": {...},                // Wrong: missing category
  "User Details - First Name": {...}, // Wrong: wrong delimiter
  "user.first_name": {...}            // Wrong: dot notation
}
```

**Value Object Structure:**
Each value object MUST contain:
- `value`: The extracted value (string, even for numbers)
- `source`: Source reference (e.g., "transcript 05:23", "contacts.csv row 2", "contract page 3")
- `status`: One of: "Complete", "Partial", "Missing", "Inferred", "Conflict"
- `notes`: (optional) Additional context or confidence indicators

#### 1. Provisioning CSV Format

Use generate_provisioning_csv tool to create data/[OPPORTUNITY_ID]/provs/[OPPORTUNITY_ID]_provisioning.csv

Structure: Category;Attribute;Sub-Attribute;Required/Optional;Extracted Value;Source Timestamp;Status;Notes

The tool will automatically map the attributes_data dictionary to the CSV template format.

Include all 80 attributes from the requirements template, marking:
- Status: Complete/Partial/Missing/Not Required/Conflict
- Source Timestamp: Reference to source (e.g., "transcript 05:23-05:45", "spreadsheet users.xlsx", "contract BOF_signed.pdf")
- Notes: Additional context, confidence scores, or issues

CRITICAL: Use validate_attributes tool to ensure all 80 attributes are properly populated.

#### 2. Status Report (Markdown)

VERY IMPORTANT: You cannot generate the Status Report without having run the validate_attributes tool first.

Use generate_status_report tool to create data/[OPPORTUNITY_ID]/provs/[OPPORTUNITY_ID]_status.md

Include:
- Executive Summary (completeness %, critical missing items, confidence level, implementation readiness)
- Data Sources Analyzed (Salesforce records, transcripts, documents)
- Provisioning Requirements (Complete/Partial/Missing categories)
- User Details, Infrastructure, Configuration summaries
- Data Quality Metrics (explicit/inferred/low confidence data points, conflicts)
- Next Steps (immediate actions, customer follow-up, implementation readiness)
- Notes and Observations

## Adaptive Strategies

### When Limited Data Available:
1. Search for related accounts (parent/child companies)
2. Check for historical opportunities
3. Look for email threads in tasks/activities
4. Search feed items for discussions
5. Check for custom objects specific to telecom

### When Conflicting Data Found:
1. Prioritize most recent information
2. Weight official documents over conversations
3. Flag conflicts in status report with STATUS_CONFLICT
4. Request clarification in next steps

### Special Considerations:
- **N11 Extensions** (311, 411, etc.): Flag for reassignment
- **Paging Systems**: Verify SIP compatibility
- **Multi-site**: Map location relationships clearly
- **Number Porting**: Verify all numbers with current carrier
